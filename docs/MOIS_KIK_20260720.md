# MOIS KIK administrative/legal code snapshot — 2026-07-20

## Status

Verified from the supplied official layout document plus the paired fixed-width and XLSX files.

This snapshot is useful for the Atlas KR **current Region Registry and administrative-dong ↔ legal-dong crosswalk**.

It is **not sufficient by itself for historical change tracking**, because all three supplied 2026-07-20 snapshots have blank `말소일자` values. Historical split/merge/rename/abolition events still need separate change-history notices or older snapshots.

## Official layout meaning

The supplied layout defines:

- `행정동` as the administrative agency/eup-myeon-dong that administratively governs legal-dong areas.
- `행정동코드` and `주민등록 행정기관코드` as the same term.
- `법정동` as the legal-address unit used in official records and addresses.

Files:

1. `KIKcd_H.YYYYMMDD` — administrative-agency/admin-dong codes
2. `KIKcd_B.YYYYMMDD` — legal-dong codes
3. `KIKmix.YYYYMMDD` — administrative-dong to governed legal-dong relations

## Snapshot limitation

Counts of non-empty `말소일자` in the supplied files:

```text
KIKcd_H  0
KIKcd_B  0
KIKmix   0
```

Therefore interpret these as the **2026-07-20 active/current code snapshot**, not a complete historical ledger.

For historical reproducibility Atlas still needs one or both of:

1. ordered older KIK snapshots, or
2. official change-history notices containing creation/abolition/split/merge/rename events.

## Atlas implementation

Parser: `lib/mois/kik.ts`

Rules:

- preserve all 10-digit native codes as strings;
- decode raw files as EUC-KR/CP949-compatible text;
- use byte offsets, not Unicode character positions, for fixed-width raw files;
- normalize dates to ISO `YYYY-MM-DD` internally;
- keep KIK H/B entities independent;
- keep KIKmix as `admin-legal-crosswalk` relations;
- do not infer spatial boundary geometry from these code files;
- attach boundary geometry later from a separately versioned boundary dataset.
