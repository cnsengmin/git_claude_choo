# 시점별 행정구역 레이어와 연결표 — 통합 설계안 v2.1 (승인 대기)

작성 2026-10-22, 브랜치 `feature/region-crosswalk`. v1(기준 경계 하나에 맞추는 방식)을 대체한다. v2.1: 선행 자료(admdongkor·국가데이터처 연계정보·KIRD) 쓰임새 반영.

## 0. 왜 바꾸나

시군구·행정동 수는 계속 바뀐다(기초 단위 2010 230 → 2014 229 → 2026-07 230). "기준 경계 하나"를 정하고 그 단위 수를 코드에 고정하면, 단위가 바뀔 때마다 228/229 같은 오류가 다시 생긴다.
그래서 **단위 목록과 변경 사건은 행정안전부 공식 기록에서 시점별로 만들고, 경계 겹침은 가중치 계산과 검증에만 쓴다.**

## 2. 데이터 모델

### 2-1. 단위 레지스트리 `region_units` (행안부 코드 기준, 시점 무관 한 표)

`code`(10자리 문자열), `code5`(시군구 5자리, 표시용), `level`(`sido` / `lgu` / `general_gu` / `sub_office` / `admin_dong` / `dong_sub_office`), `name`, `sido_name`, `parent_code`, `valid_from`, `valid_to`(말소일 전날, 현행은 비움), `source_snapshot`.
- `level`은 이름 구조와 출장소 표기로 판정하고, 코드 자르기로 만들지 않는다. 일반구 → 시는 같은 시점에 살아 있는 같은 시도의 "OO시" 행을 이름으로 찾는다.
- 출장소 판정은 행안부 이름 표기("…출장소")를 기본으로 하고, admdongkor `find_offices()` 목록과 대조해 어긋나는 코드를 검토 목록에 올린다.
- Atlas의 `AtlasRegionRef`에 이미 `validFrom`/`validTo`가 있어 그대로 담긴다. `atlasRegionId = kr:<type>:<code>:<validFrom>`이라 같은 코드의 재사용도 구분된다.

### 2-2. 변경 사건 `region_events` → `AtlasRegionRelation`

같은 날 말소된 코드와 생성된 코드를 한 사건으로 묶는다.
- `recode`: 경계는 그대로, 코드·시도만 바뀜(강원 42→51 2023-06-11, 군위 47720→27720 2023-07-01, 전북 45→52 2024-01-18, 광주·전남 → 12 2026-07-01). 판정: 같은 이름 + 경계 겹침 95% 이상.
- `rename`: 코드·이름이 바뀌고 경계는 그대로(인천 남구 → 미추홀구 2018-07-01).
- `merge` / `split` / `new` / `abolished`: 그 밖. 대상 관계와 몫은 경계 겹침으로 정한다. 겹침 계산은 admdongkor `match_adm()`을 쓰고, 사건 시행일 직전·직후 경계 버전을 넣는다.
- 경계로만 보이는 변화(공식 사건 없음)는 admdongkor `compare()`로 찾아 `boundary-change` 후보로 기록만 하고, 공식 사건이 없으면 연결표에서는 1:1을 유지한다.
- 사건마다 근거를 남긴다: 행안부 시행일, 이름 대응, 겹침 비율, 게시물 URL. 게시물 설명과 다르면 사람 검토 목록에 올린다.
- 출장소의 생성·폐지는 단위 변경이 아니므로 사건에서 뺀다(화성시동부출장소 폐지 2026-02-01 등).

### 2-3. 시점별 레이어 `layer = (level, 기준일)`

- 이름 예: `kr-lgu@2025-12-31`(229), `kr-lgu@2026-10-01`(230), `kr-sgg@2025-12-31`(일반구 구분 252), `kr-admdong@2025-12-31`.
- 내용: 그 날 살아 있는 단위 목록(레지스트리에서 계산) + 그 날에 가장 가까운 이전 경계 버전. 경계는 admdongkor `get(<버전>)`으로 불러오고, 쓴 버전 이름을 레이어 manifest에 남긴다.
- **레이어 검증**: 경계 버전의 단위 집합 = 레지스트리의 그 날 단위 집합. 다르면 그 레이어는 `boundary_mismatch`로 표시하고 차이를 남긴다. 2026 하반기처럼 경계 공급이 늦은 시점에 생긴다.
- 기본 제공: 매년 12월 31일 레이어(주민등록 연말 통계와 맞춤). 그 밖의 날짜는 요청 시 만든다.

### 2-4. 연결표: 이웃 시점끼리만 만들고, 임의의 두 시점은 이어 붙여 계산

- 저장: 연속한 두 레이어 사이의 엣지 `(from_layer, to_layer, from_code, to_code, w_src, w_tgt, method, event_id)`.
- 2015 → 2025 같은 요청은 2015→2016→…→2025를 곱해서 만든다. 기준 경계를 미리 하나로 정하지 않는다.
- `method`는 v0.2의 규칙을 잇는다(`code_1to1`, `recode`, `area_abolished_code`, `area_ceded_to_new`). 사건이 없는 단위는 경계가 달라 보여도 1:1이다(한강 수면 재작도 문제 차단).
- admdongkor `match_adm()`은 순수 면적 가중이라 그대로 쓰지 않는다. 사건이 있는 단위에만 그 결과를 쓰고, v0.2의 잡음 제거 규칙(폭 20m 미만 띠, 0.2%·5,000㎡ 미만 조각, 새 단위로 가는 조각은 유지)을 덧씌운다.
- 인구 가중: 집계구 경계 2025 + 사건 시점에 가까운 집계구 통계(2015·2020·2024)로 `w_src_pop`·`w_tgt_pop`을 함께 계산하고, 조각에 사람이 없으면 면적 몫을 쓴다.

### 2-5. 다른 코드 체계 대응 `code_map`

통계청 5자리, 고용조사 4자리, 2026-07 이후 KOSIS 7자리는 **레이어별로** 행안부 단위에 붙인다(`code_map@2025-12-31` 등). 만드는 방법은 `scripts/sgg2025/build_code_map.py`와 같다(경계 겹침 + 이름, 앞자리 자르기 금지).

**검증: 국가데이터처 법정동 연계정보와 대조**
- 연계정보의 (행정구역분류코드, 행정기관코드) 쌍을 시군구 수준으로 모아, `code_map`의 (통계청 코드, 행안부 코드) 쌍과 비교한다. 연계정보 판의 기준일(2025-06-02판)과 가장 가까운 레이어에서 비교한다.
- 결과는 세 갈래로 남긴다: 일치 / 연계정보에만 있음 / 우리에만 있음. 불일치 건마다 그 사이 행안부 사건(시행일)으로 설명되는지 표시하고, 설명되지 않는 건은 사람 검토 목록에 올린다.
- 통과 기준: 그 시점에 살아 있는 시군구 쌍이 사건으로 설명되는 건을 빼고 100% 일치.

## 3. 기존 산출물 처리

- `kr-sgg-crosswalk v0.2`: 버리지 않고 v0.3에서 위 레지스트리로 다시 만든다. v0.2의 기초 단위 228개(증평군 누락, 자치구 8곳 코드 오류)는 `sggcd[:4]+"0"` 버그다.
- 2025 단년도 표(`data/derived/sgg2025/`): `kr-lgu@2025-12-31` 레이어의 첫 통계 표로 그대로 쓴다. 단위 수 229는 레지스트리와 일치한다.
- 서울 행정동 패키지 v0.1: 기준 `kr-admdong@2026-10-01`(서울 427)로 이름만 맞춘다.

## 4. 갱신 절차

1. 행안부 게시판에 새 변경내역이 올라오면 그 게시물의 `말소코드포함` 파일을 받는다(receipt + SHA-256).
2. 레지스트리를 다시 만들고, 직전 판과 비교해 새 사건만 뽑는다.
3. 새 사건의 경계 겹침·게시물 설명 대조 → 엣지 추가.
4. 해당 연말 레이어와 그 뒤 레이어만 다시 계산한다.

## 5. Atlas KR 반영

- 타입(`lib/atlas-registry/types.ts`): `AtlasRegionRelationType`에 `recode` 추가. `AtlasLayerVersion { id, level, referenceDate, unitCount, boundaryVersion, status }`, `AtlasCrosswalkEdge { fromLayer, toLayer, fromCode, toCode, wSrc, wTgt, wPop?, method, eventId }`, `AtlasCodeMapEntry { layer, codeSystem, code, baseCode, method, evidence }` 추가.
- `AtlasRegionType`은 그대로 두고, 기초 단위와 일반구 구분은 레이어 `level`로 한다.
- 데이터셋 목록(`datasets.ts`): `mois-kik-with-abolished-<날짜>`(원천), `atlas-region-registry`, `atlas-region-layers`, `atlas-crosswalk-edges`, `atlas-region-code-map`, `atlas-sgg-single-year-2025`.
- 구현(P7): 연결 엣지는 설계의 `wPop` 대신 원천·대상 인구 몫 `wSrcPop`·`wTgtPop`을 함께 두고, 기준 레이어까지 이어 붙인 표는 `AtlasCrosswalkRow`로 읽는다. 관계 유형에는 `reorganize`·`absorbed`도 더했다. 리더는 `lib/atlas-data/region-registry.ts`(서버 전용, CSV만; 행정동 엣지는 Parquet에만 있어 읽지 않는다).
- 원칙은 v1과 같다: Python이 CSV/Parquet + manifest를 만들고, TS는 읽기만 한다. 기존 `REGION_REGISTRY_META.policy`("코드와 유효기간을 보존하고 과거 코드를 덮어쓰지 않는다")와 맞는다.

## 6. 알려진 한계

- 행안부 자료는 선후 관계를 주지 않는다. 분할·통합의 몫은 경계로 계산하므로, 경계 버전이 없는 시점에는 확정할 수 없다.
- SGIS 연도 경계의 기준일은 연말이 아니다(2025는 2분기, 2025-06-30). 하반기 변경은 레이어 검증에서 차이로 드러난다.
- 경계 원자료가 시점마다 일관되지 않다: 비무장지대·군사분계선 북쪽 면(파주 장단·진동·진서, 철원 근동·원동·원남·임남, 고성 수동)은 판에 따라 경계가 있거나 없고, 연말 판이 없는 해(2016·2017·2018·2020·2021·2022)가 있다. 레이어 대조 결과(`layer_boundaries.csv`)에 갈래별로 남기고, 연결표는 사건 시행일 앞뒤 판을 쓴다.
- admdongkor의 통계청 코드는 2026-07 개편 지역에서 공식과 다르다(시군구 12개, 행정동 257개). 공식 연계정보 개정판이 있는 레이어는 공식 코드를 쓰고, 2025-10 이전 레이어는 경계판 코드를 쓴다. 연계정보 파일은 2025-10-01판부터만 있어 2008–2024 레이어의 통계청 코드는 공식 대조를 거치지 않았다.
- 인구 가중은 2025 집계구 경계 위의 2015·2020·2024 인구로 계산한다(SGIS는 2010 집계구 인구를 주지 않음). 변경 뒤 개발된 땅(세종·위례 등)은 사건 직전 인구가 없으면 몫이 틀어진다(공주시→세종 2012: 면적 8.2%, 2015년 인구 18%). 그래서 면적 몫(`w_src`)과 인구 몫(`w_src_pop`)을 함께 제공한다.
- 기존 단위가 새 단위에 내준 땅은 1% 이상이면 나눈다(v0.2의 5%보다 낮춤, 청원군→세종 3.4% 때문). 행정동 수준의 5% 미만 조각은 같은 시·군·구 안의 새 단위로만 보낸다.
- 2026-07 이후 경계는 SGIS에 아직 없다. 후보: vuski 2026 버전, 도로명주소 구역도형(월 갱신).
- 1988년 이전 코드는 행안부 파일의 생성일이 1984·1988년으로 몰려 있어 실제 생성일이 아닐 수 있다. 패널은 2008년 이후부터 제공한다.

- admdongkor 패키지는 import할 때 인덱스를 인터넷에서 받아 온다(`dist/data/`). 재현성을 위해 쓴 패키지 버전과 경계 버전 이름을 manifest에 고정하고, 받은 경계는 원자료 폴더(`data/raw/`)에 캐시한다.
- 출처표시: 산출물에 SGIS(공공누리 1유형), admdongkor(CC BY 4.0), KIRD를 대조에만 쓴 경우 그 사실을 함께 적는다. KIRD 데이터 자체는 재배포하지 않는다.

## 7. 승인 받을 결정

1. 이 v2 구조(공식 기록 기반 레지스트리 + 시점별 레이어 + 이웃 시점 연결표)로 간다. 경계 매칭은 admdongkor 재사용, 코드 대응은 연계정보로 검증, 변경 사건은 KIRD와 대조(1-1, 2-5, 2-6).
2. 기본 제공 레이어 범위: 2008–2025 연말 + 2026-10-01(현재).
3. 경계 GPKG 보관: GitHub Release 첨부(권장) 또는 비공개 데이터 저장소.
4. R 비교 검사: GitHub CI에서만(권장) / 이 PC 설치 / 생략.
